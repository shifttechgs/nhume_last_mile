# Send Parcel — Feature Documentation

## Overview

The Send Parcel feature allows a sender (guest or authenticated) to post a parcel delivery request through a 3-step wizard. On completion a `Task` record is persisted and an order number is issued for tracking.

---

## User Flow

```
GET /send
  └─ ParcelController::create()
       └─ renders pages/send.blade.php
            └─ @livewire('parcel.create-order-wizard')

Step 1 — How are you sending?
  ├─ Drop at shop (WalkIn)       → user selects a collection point
  └─ Biker picks up (BikerCollection) → user enters pickup address

Step 2 — Parcel details
  ├─ Delivery address + recipient
  ├─ Category, weight, fragile toggle
  ├─ Schedule: now or later (datetime picker)
  └─ Live price preview updates as user fills in fields

Step 3 — Confirmation
  ├─ Order number displayed (copy-to-clipboard)
  ├─ Contextual next-step message (drop off vs await biker)
  └─ Links to /track/{order_number} and "Send another"
```

## Architecture

### Entry Point
| Layer | File | Responsibility |
|---|---|---|
| Route | `routes/web.php` | `GET /send → ParcelController@create` |
| Controller | `app/Http/Controllers/ParcelController.php` | Returns the send page view |
| View | `resources/views/pages/send.blade.php` | Page shell, nav, footer |
| Livewire | `app/Livewire/Parcel/CreateOrderWizard.php` | All UI state, wizard flow, validation |

### Order Placement Chain

```
CreateOrderWizard::placeOrder()
  │  Builds CreateTaskDTO from form properties
  │
  └─ ParcelOrderService::placeOrder(CreateTaskDTO)
       │
       └─ CreateTaskAction::execute(CreateTaskDTO)
            ├─ GenerateOrderNumberAction::execute()
            │    └─ TaskRepository::orderNumberExists() — collision guard loop
            ├─ CalculateTaskPriceAction::execute(CreateTaskDTO)
            │    └─ Pure calculation, no DB calls
            └─ TaskRepository::create(array)
                 └─ Task::create() — single Eloquent call
```

### DTO: `CreateTaskDTO`

```php
final readonly class CreateTaskDTO
{
    public function __construct(
        public PickupType      $pickupType,
        public ServiceType     $serviceType,
        public OrderSource     $orderSource,
        public string          $dropoffAddress,
        public string          $recipientName,
        public string          $recipientPhone,
        public PackageCategory $packageCategory,
        public ?int            $collectionPointId,
        public ?string         $pickupAddress,
        public ?string         $itemDescription,
        public ?float          $weightKg,
        public bool            $isFragile,
        public ?string         $notes,
        public ?Carbon         $scheduledAt,
        public ?int            $userId,
    ) {}
}
```

## Pricing

Calculated by `CalculateTaskPriceAction`. Constants:

| Component | Amount | Condition |
|---|---|---|
| Base delivery | $2.50 | Always |
| Biker collection fee | +$2.00 | `PickupType::BikerCollection` |
| Weight surcharge | +$0.50/kg | Per kg above 5 kg |
| Fragile handling | +$1.00 | `is_fragile = true` |

**Examples:**
- Walk-in, 2 kg, not fragile → **$2.50**
- Biker, 2.5 kg, not fragile → **$4.50**
- Walk-in, 8 kg, fragile → **$5.00** (2.50 + 1.50 + 1.00)

The Livewire component maintains a `priceEstimate` computed property for live UI preview using the same constants. The persisted price on the `Task` record is computed by the action on submission.

## Validation

### Step 1
| Field | Rule |
|---|---|
| `pickup_type` | `required\|in:walk_in,biker_collection` |

### Step 2
| Field | Rule | Condition |
|---|---|---|
| `dropoff_address` | `required\|string\|min:5` | Always |
| `package_category` | `required\|in:<enum values>` | Always |
| `recipient_name` | `required\|string\|max:100` | Always |
| `recipient_phone` | `required\|string\|max:20` | Always |
| `collection_point_id` | `required\|exists:collection_points,id` | Walk-in only |
| `pickup_address` | `required\|string\|min:5` | Biker only |

## Order Number Format

```
NHM-YYYYMMDD-XXXX
     └─ date   └─ 4 random chars from A-Z2-9 (no 0/O/1/I to avoid confusion)

Example: NHM-20260814-8E5H
```

Generated by `GenerateOrderNumberAction`. Collision-safe via a `do/while` loop checking `tasks.order_number` uniqueness. Probability of collision at current scale is negligible.

---

## Database

All data is written to the `tasks` table. Key columns populated on creation:

| Column | Value |
|---|---|
| `order_number` | Generated (`NHM-YYYYMMDD-XXXX`) |
| `status` | `TaskStatus::Posted` |
| `service_type` | `ServiceType::LastMileDelivery` |
| `order_source` | `OrderSource::Online` |
| `pickup_type` | From wizard step 1 |
| `pickup_address` | Collection point address (walk-in) or user input (biker) |
| `collection_point_id` | FK to `collection_points` (walk-in only, else `null`) |
| `price_estimate` | Computed by `CalculateTaskPriceAction` |
| `offered_price` | Same as `price_estimate` at creation |
| `scheduled_at` | Parsed datetime or `null` (ASAP) |

## What's Not Built Yet

- SMS / WhatsApp notification on order creation
- Transporter matching / assignment
- Payment capture
- Parcel photo upload
- Guest order tracking (currently stores `user_id = null` for unauthenticated users — retrieval is by order number only)
